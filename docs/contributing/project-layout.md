# Project layout

A tour of the repository, mapped to the recommended layout of [brief §11](../self-improvement-software-factory-decision-brief.en.md#11-recommended-repository-layout) and to the three zones of brief §2. The zone of each runtime unit is fixed by `pkg/manifest` (see `.sisf/factory.yaml`). Each package's doc comment (`go doc ./<dir>`) says what it owns; this page only routes you there.

## Binaries (`cmd/`)

| Directory | Zone | What it is |
|---|---|---|
| `cmd/sisf/` | operator | The command line: `init`, `up`, `doctor`, `down`, `status`, `login`, `call`, `conformance check`, `emergency-stop` and the simulators `sim github` and `sim oidc` (`go run ./cmd/sisf help`). New commands go in `cmd/sisf/cmd_<area>.go`. |
| `cmd/factoryd/` | 3 and 2 | The factory's own units: `factoryd control` (Zone 3) and `factoryd dispatcher` (Zone 2). `cmd/factoryd/wiring/` connects the packages below into a running process. |
| `cmd/supervisor/` | 3 (trusted) | The trusted release supervisor, a separate binary in its own image. Its build, QA, landing and release stages are in `cmd/supervisor/stages/`. |
| `cmd/edge/` | shared | The reverse proxy in front of the application (the `edge` unit, which every zone uses); it keeps the per-revision counters a release monitor reads. |

## Contracts (`pkg/`)

Brief §3 and §11 place the replaceable interfaces here. They are experimental until 1.0 and change additively ([ADR 0016](../adr/0016-oss-governance.md)).

| Directory | Contract |
|---|---|
| `pkg/core/` | Shared types: states and events, actions, actors, errors, receipts, budget, policy. `pkg/core/statemachine/` is the issue lifecycle of brief §5.2. |
| `pkg/agent/`, `pkg/execution/`, `pkg/deploy/` | Agent backends, execution sandboxes, deployment backends (brief §3.1 to §3.3). |
| `pkg/identity/`, `pkg/state/`, `pkg/secrets/`, `pkg/telemetry/`, `pkg/github/` | Brief §3.4. |
| `pkg/qa/`, `pkg/approvals/`, `pkg/decision/` | Independent evaluation, human approval, the Decision Layer contract. |
| `pkg/manifest/` | The Go types of `factory.yaml`; the schema is `schemas/factory.schema.json`. |
| `pkg/conformance/` | The self-grading kit for backend authors. |

## Implementation (`internal/`)

| Directory | Brief | What it does |
|---|---|---|
| `internal/conformance/` | §2 | The three-zone conformance checker for a factory manifest. |
| `internal/install/` | §10 | Creates, starts, checks and stops one deployment (`sisf init/up/doctor/down`). |
| `internal/intake/` | §5 | Takes a GitHub issue from intake to a scoped, approved work item. |
| `internal/dispatcher/` | §5.2 | Hands Ready issues to an agent backend under a lease, with fencing. |
| `internal/agentrun/` | §3.5 | Model selection and the fresh context of each run. |
| `internal/qa/` | §6.1 | The independent evaluator and its hard gates. |
| `internal/supervisor/` | §6.2, §6.3 | The supervisor boundary and the release pipeline (`release/`). |
| `internal/supplychain/`, `internal/signing/` | §7 | Supply-chain evidence; signing keys and delegation. |
| `internal/actions/` | §9 | The one action service behind every surface; the action sets are in its subpackages. |
| `internal/control/`, `internal/mcp/`, `internal/oauthas/` | §9 | The HTTP server (dashboard, REST, WebMCP), remote MCP and its authorization server. |
| `internal/auth/`, `internal/rbac/` | §7 | Sign-in, roles and per-action authorization. |
| `internal/policy/`, `internal/decision/`, `internal/budget/` | §4.1, §4.2, §8 | Foundation files, the Decision Layer, budget gates. |
| `internal/audit/`, `internal/redact/`, `internal/secretbroker/`, `internal/egress/`, `internal/dockerfilter/`, `internal/edge/`, `internal/catalog/` | | Audit log, redaction, per-run secrets, outbound policy, the Docker access filter, the edge proxy, the feature catalog. |
| `internal/testkit/` | | Shared test fakes: `fakegithub`, `fakeoidc` and the in-process `harness`. |

## Everything else

| Path | Brief | What it holds |
|---|---|---|
| `adapters/agent/{claude,codex,pi,fake}/` | §11 | Agent backends. `fake` is scripted, for tests and simulated installs. |
| `adapters/exec/{local,docker}/`, `adapters/deploy/{local,compose}/` | §11 | Execution and deployment backends for the two supported modes. Other backends listed in §11 are not built yet; see the [capability matrix](../capability-matrix.md). |
| `ui/` | §9 | The dashboard: templates and static assets. |
| `templates/` | §11 | The files an install is generated from: Compose and Standalone service units. |
| `build/` | §10 | Dockerfiles of every image, base images pinned by digest. |
| `api/` | §9 | `openapi.yaml` and `llms.txt`, generated by `make generate`. Do not edit by hand. |
| `schemas/` | §11 | JSON schema of the factory manifest. |
| `examples/hello-app/` | §11 | The sample Zone 1 application; see its [README](../../examples/hello-app/README.md). |
| `.sisf/` | §4.1 | The example instance policy (`factory.yaml`). |
| `docs/adr/`, `docs/guides/` | §11 | Decisions and the operator guides. The security policy is [docs/SECURITY.md](../SECURITY.md). |
| `tests/` | §13 | Cross-package suites; see [testing.md](testing.md). |
| `AGENTS.md`, `REVIEW.md`, `DECISIONS.md`, `FEATURES.md` | §4.1 | Foundation files; precedence is in [ADR 0003](../adr/0003-policy-precedence-and-foundation-files.md). Change them only through a reviewed PR the Owner approves. |
